# 0026 – NDI®, option de compilation désactivée par défaut

- Date : 2026-10-17
- Statut : Acceptée

## Contexte

Le cahier des charges (phase 3) demande l'entrée et la sortie NDI, pour échanger de la vidéo avec les autres machines du réseau. NDI est un protocole propriétaire : la bibliothèque `libndi` est gratuite mais soumise au contrat de licence du NDI SDK. Les en-têtes du SDK sont sous licence MIT.

Le contrat (§3d) demande que tout produit distribué qui utilise le SDK soit livré sous une licence d'utilisation reprenant ses interdictions (pas de rétro-ingénierie ni de modification du SDK, garanties exclues, copyright de NDI). Prism est sous MIT / Apache 2.0. Le §3f encadre l'usage de la marque NDI® : seulement pour dire que le produit est compatible, avec une mention claire de la marque.

## Options

1. **NDI intégré et actif par défaut**, en chargeant la bibliothèque installée par l'utilisateur, comme les greffons NDI open source existants. Risque juridique résiduel sur le §3d pour les versions publiées.
2. **Module NDI séparé, désactivé par défaut** : même code, derrière une option de compilation `ndi` ; les versions publiées ne l'activent pas tant qu'un juriste n'a pas tranché.
3. **Pas de NDI pour l'instant** : Syphon couvre déjà l'échange sur un même Mac.

## Décision

Option 2, choisie par l'observateur (@ouimarcelin) :

- option `ndi` des crates `prism-io-video`, `prism-engine` et `prism-app`, désactivée par défaut (`cargo run --release -p prism-app --features ndi`) ;
- déclarations FFI écrites d'après les en-têtes MIT, attribution dans `NOTICE` ; aucun fichier du SDK copié dans le dépôt, la bibliothèque n'est pas livrée ;
- `libndi` chargée à l'exécution (`libloading`) : variable `NDI_RUNTIME_DIR_V6`, puis `/usr/local/lib`, puis le dossier du SDK ; absente, NDI est grisé avec la raison, Prism démarre quand même ;
- sortie : image programme convertie en BGRA sur le GPU, relue avec trois tampons sans attendre le GPU, envoyée par un thread à soi (une image au plus en attente : un réseau lent perd des images au lieu de ralentir le moteur), sous le nom « Prism » ;
- entrée : un récepteur par clip, sur son propre thread, demande du BGRA (`BGRX_BGRA`), garde la dernière image, envoyée au GPU comme celle d'une caméra ; « en attente » tant que la source est absente ;
- marque écrite « NDI® » dans l'interface, avec la mention « NDI® est une marque déposée de Vizrt NDI AB » ;
- la CI compile aussi avec l'option ; les tests NDI passent sans rien vérifier quand la bibliothèque manque.

## Conséquences

- Avant d'activer `ndi` dans une version publiée : avis juridique sur le §3d (licence d'utilisation de l'application livrée) et sur les règles de marque.
- Son NDI non géré (ni envoyé ni reçu) ; programme envoyé en alpha prémultiplié comme pour Syphon.
- macOS seulement pour l'instant (dépendance `prism-io-video` propre à macOS) ; le code de chargement prévoit Windows et Linux.
