# 0033 – DMX sur le réseau : Art-Net et sACN

- Date : 2026-10-17
- Statut : Acceptée

## Contexte

La phase 5 demande d'envoyer des couleurs à des luminaires DMX (pixel mapping) et de recevoir le DMX d'une console. Les deux protocoles réseau courants sont Art-Net (spécification publique d'Artistic Licence) et sACN (norme ANSI E1.31, publique). Le cahier des charges cite les crates `artnet_protocol` et `sacn`.

## Options

1. **Les crates citées** : plus de code tiers à suivre (licences, dépendances) pour quelques dizaines d'octets d'en-tête.
2. **Nos propres paquets** : seul le paquet de données DMX de chaque protocole est utile ici ; il tient en une centaine de lignes, testées octet par octet.

## Décision

Option 2, crate `prism-dmx` :

- Art-Net : paquet ArtDmx (identifiant, code 0x5000, version 14, séquence, univers sur 15 bits, 512 canaux), port 6454, envoi à une adresse ou en diffusion ;
- sACN : paquet de données (couches racine, trame et DMP), port 5568, envoi au groupe multicast de l'univers (239.255.x.y) ou à une adresse ; priorité 100 ; identifiant de source tiré au lancement ;
- un `DmxSender` par sortie ; un envoi qui ne passe pas tout de suite est abandonné (l'image suivante renvoie l'univers) ;
- les paquets reçus se lisent avec `artnet::parse_dmx` et `sacn::parse_data`.

## Conséquences

- Pas de découverte des appareils (ArtPoll) ni de synchronisation sACN : à ajouter si un appareil l'exige.
